# 短剧聚合・柏霖

主模块 0.4.4，以 0.4.3 为基准检查修正。按使用者要求发布未加密 JavaScript，合集只提供主模块。

## 导入

下载 [iphone.rex](https://raw.githubusercontent.com/kenxtbecdi7690/rex-home/main/shortdrama/iphone.rex)，保存到 iPhone「文件」，点开选择 Rex；或用 Rex 的「导入配置」。这是独立的短剧首页，包含红果、七猫、河马、星芽、好看五行，自动引用本目录的 ShortDrama.js。

在截图中的「模块」页添加合集时，填写以下地址，然后进入合集安装「短剧聚合・柏霖」：

```
https://raw.githubusercontent.com/kenxtbecdi7690/rex-home/main/shortdrama/manifest.json
```

这个入口读取合集 JSON；直接传 JS、普通 ZIP 或 test.mjs 会用错格式。`.rex` 是首页配置包，使用「导入配置」，不从模块合集入口添加。

## 验证与错误修正

0.4.4 修正检查时重现的问题：

- 搜索明确设置 Rex 的 `cacheDuration: 300`，不依赖宿主的默认值；播放功能补齐空 `params`，缩短会挤压设置画面的选项名称。
- 红果分集只共用一层 60 秒模块快取，`loadDetail` 与 `loadResource` 不再把同一旧地址重新缓存 60 秒；含首集预载的详情缓存也不超过该首集原始缓存期限。Rex 自身缓存与持有的播放画面仍待实机验证。
- 红果详情核对请求的剧集 ID；公开可用性必须是布尔值 `true`，错误 ID、`false`、缺值及非布尔值均拒绝。
- 同时取得装置 ID 与星芽访客权杖时合并请求，避免并发创建不同访客身份或重复登入。
- 喜番补查 manifest 与 adaptationSet 层级的隐藏／加密标记；抖音补查影片与地址层级的隐藏／受保护标记。
- 柚漫剧过期详情重新搜索前移除旧记录，搜索结果已没有本剧时明确报错，不再继续使用旧播放地址。

保留模组 ID `bolin.shortdrama.original`；合集与 JS 的版本都是 `0.4.4`。`iphone.rex` 的格式版本 `1` 是首页包格式，不是模块版本，不应改成 `0.4.4`；其五行仍引用同一模块 ID 与 main 的 JS 地址，函数、参数与 13 个格子字段均已核对。

离线检查命令（在储存库根目录执行）：

```sh
node --check shortdrama/ShortDrama.js
node shortdrama/test-contract.mjs
node shortdrama/test-cache.mjs
node shortdrama/test-quality.mjs
node shortdrama/test-sources.mjs
```

结果：10 项结构／回归检查、原有快取与画质检查、九来源 58 组预设／分类、9 条详情与播放解析流程、7 种搜索模式通过。fixture 中会模拟执行分集 `loadDetail`，不代表 Rex 会在播放器内这样调度；尤其好看、抖音的 `type:detail` 分集仍需实机逐集确认。

在线抽查用 `node shortdrama/test-live.mjs hongguo hema qimao xingya haokan weiguan youman douyin xifan`；未指定来源不会发出请求。它每来源只抽一部剧及一条媒体，使用测试环境自己的临时访客身份，不读取个人帐号，也不把权杖或带签名的媒体地址写进报告。结果保存到 `verification-live.json`；完整汇总见 `verification.json`。HTTP 206 和 MP4 开头只证明这次媒体请求成功，不是整集播放、全部剧集、HLS 子分片或 iPhone Rex 验收。

红果这次样本《一念沉沦，霍总心动了》的公开页面标示为 **360 × 640（360p）**，没有提供 1080p 多画质列表。首集 MP4 请求成功，第二集来源未开放公开播放，模块明确拒绝。不能保证红果有 1080p；官方 App 的画质不等于公开网页可取得的画质。

0.4.3 为九个来源统一加入 Rex 本机数据缓存：列表与搜索 300 秒，详情与播放线路 60 秒。缓存按来源、分类、页码、查询词或链接分别保存；模块版本改变自动失效；相同并发请求合并，错误与部分失败搜索不缓存。最多保存 60 笔，并限制总文本大小；无法写入本机储存时仍可使用内存缓存。缓存的是 JSON 数据与短效播放网址，不是离线影片。可用 `node test-cache.mjs` 运行独立缓存验证。

0.4.3 同时统一最高画质选择：多版本优先比较实际分辨率，同分辨率再比较码率；没有尺寸时使用来源的画质标签或网址内明确标示的分辨率，只有一个版本时保留原网址。好看／柚漫剧不再固定封顶 1080p，围观支持来源实际返回的 4K 标签，喜番比较尺寸与码率并排除音频轨、隐藏与加密版本，抖音比较同一分集回传的默认与 bit_rate 版本，河马比较现有 MP4／HLS 字段。仅从来源真实回传的网址中选择，不改写 360p 为 1080p。当前红果公开页面样本只有 360p，七猫与星芽接口样本各只提供一个播放网址；不能据此承诺这些来源存在更高清版本。可用 `node test-quality.mjs` 运行画质选择验证。

0.4.2 修正红果分集打开后没有播放线路的问题：原来分集只有详情页，播放器可能直接打开分集而不再次执行 loadDetail。现在使用 type:url 的分集身份，并注册 Rex 的 loadResource 播放线路入口；首页打开时预载第一集的 videoUrl，其余分集在点播时解析，避免一次请求几十集。解析时核对剧集 ID 与分集 ID，无法取得时明确报错，不用其他集替代。Rex 真机结果仍待验证。

0.4.1 修正了原交付缺少合集 manifest、可下载 JS 地址与 `.rex` 首页的问题；补上 requiredVersion，保留原模块 ID，避免产生重复模块。集合条目与 JS 的 ID／版本一致。首页使用实际函数名、完整的 13 个格子字段和参数默认值。

已通过 JS 语法、离线接口与解析检查、合集结构、首页 ZIP 与函数引用检查。网络抽查结果见 verification.json。尚未连接用户的 iPhone，不能视为 Rex 真机播放验收。媒体地址会过期；详情与播放解析按上述缓存策略取得，播放器长期停留后仍可能持有旧地址，需要重新打开详情。具体地区、剧集与公开集数以来源为准。

## 帐号与实机确认

程式没有要求或读取个人手机号、密码或个人 Cookie；七猫使用本机生成的客户端标识与请求校验，星芽会进行装置访客登入，并将访客权杖保存于 Rex 本机储存。这些储存会跟随 Rex 备份，不要分享模块储存或完整备份。公开接口可响应不等于平台保证允许第三方客户端；无法承诺不限制访客身分、装置或 IP，也不能保证永不封号。遇到验签、限流、验证或未开放分集时停止使用该入口，改用官方 App。

iPhone 验收步骤：安装合集主模块 → 导入 `iphone.rex` → 确认五行 → 确认模块版本 0.4.4 → 红果分别测试首集、另一公开集、不可用集 → 回到列表测试翻页与搜索。不可用集应报错，不能播成别集。再逐一测试其他来源、App 重开后的缓存、超过 60／300 秒后的更新；目前 `rexDevice` 仍是 `not verified`。
